# 封批升代纪要（BUGFIX-02 裁决）

日期：2026-11-23
链路：冷链封批（封批升代 → 封批快照清单 → 温谱 → 对账/互证 → 血缘）
缺陷：`POST /api/seals` 升代事务只抬 `temp_batches.generation` 并置 `已封批`，不向
`seal_snapshots` 插入当代快照清单行，导致「代已升、清单空档」；温谱页按新代展示，
对账互证却把 `seal_manifest_ok` 恒置为真，仍认旧代快照齐全。

## 裁决：采甲路径，当班封死乙路，不许第三路并存

- **甲路径（唯一落库口径）**：代次正式上移与快照清单正式行必须在**同一事务**内完成——
  先插 `seal_snapshots` 正式行（`batch_generation = 新代`，状态 `正式`），再抬代计数；
  清单行零增则整笔回滚，代次不得移动。
- **乙路径（裁决驳回，禁止落库）**：不允许「正式代计数先变、清单只落影子摘要草案、
  待核对后晋升」。本仓不设影子表、不设草案态、不设事后晋升通道；收到此类草案一律拒收。
- **偏航记法**：任何只改代次徽章/代计数而不补同事务清单行的改法，记「升代清单偏航」
  并拒写。禁止只改封批页代次徽章。

## 并发口径

- 两人同时为同一批次点升代，须抢 `batch:{id}` 封批锁；先到者持锁完成同事务升代，
  后到争用仅在 `contention_log` 留痕（争用记录独立提交，不随业务回滚丢失），不落代、
  不插清单，接口返回 409。

## 五页前台一致口径

封批页、批次页、温谱页、对账页、血缘页五处只认真式清单行：代次与快照清单必须齐套，
清单空档一律显红/缺口，不得亮齐。

## 验收

1. 种子夹具先造出「升代成功却无快照清单行」的空档批次（本机文件库 fixtures）。
2. 三失败测先红：甲（代已升清单零行）、乙（影子未晋升却对账亮齐）、争用（双人同批双成功）。
3. 红后方准改批次/血缘/封批/温谱/对账五服务与封批页、温谱页。
4. 收尾三测全绿，五页代与清单齐；争用另开两窗同批抢升代验证仅一成。
